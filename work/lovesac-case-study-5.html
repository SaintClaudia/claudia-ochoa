Case Study — 05 · Heuristic Evaluation

Past the score.

A perfect Lighthouse score and a passing security grade are a starting point, not a finish line. This is the manual pass underneath the automated ones — reading raw headers instead of a badge, listening instead of assuming, and testing the actual task instead of the check that stands in for it.

August 30, 2026 · 7 min read

The Thesis

An automated score tells you a check passed. It doesn't tell you whether anyone actually had a good experience.

Lighthouse, PageSpeed, and security scanners are genuinely useful — they catch real, fixable problems fast, and every score cited earlier in this series is real. But they're pattern-matchers, not people. A heuristic evaluation is the manual layer on top: expert review against known usability principles, plus actually using the thing the way someone real would. This case study applies that layer to four claims made earlier in the series.

01 · Security Headers

A grade isn't the same as being safe.

Header scanners check whether a policy exists — not whether it's configured well, or whether one obvious gap got missed entirely. Reading the raw response headers directly tells a fuller story than a badge does.

Lovesac.com actually gets a lot right here: it ships a Content-Security-Policy, a Permissions-Policy, HSTS, and the smaller headers that are easy to skip. What it's missing is X-Frame-Options — the one header whose entire job is stopping another site from loading yours inside an invisible frame and tricking a visitor into clicking something they didn't mean to. That single gap is enough to cap an otherwise strong header set at a B.

Why this took reading raw headers, not a badge A grade only helps if you already know to go check it. This redesign's own headers weren't a given either — X-Frame-Options and Strict-Transport-Security were already in place, but Content-Security-Policy and Permissions-Policy needed a Cloudflare Worker built specifically to add them, then a headless-browser sweep of every page on the site to confirm nothing broke before it went anywhere near real traffic. The badge is the summary. The verification is the actual work.
02 · Console Health

What's running, whether you asked for it or not.

A clean-looking homepage says nothing about what's happening underneath it. Opening the console on both sites for a few seconds tells a very different story than either one tells on its own.

This redesign — live console output
0 warnings · 0 errors

Note. Captured via the Chrome DevTools Protocol against each live homepage, August 30, 2026. Third-party tracking scripts can change independent of either page.

None of this breaks the page a visitor actually sees — that's exactly what makes it easy to miss. A heuristic evaluation isn't only "does it look right," it's "what else is happening that a visual review alone wouldn't catch." Every line on the left is a third-party script — consent management, an ad pixel, an A/B testing tag — running in the background of every visit, misconfigured or not, whether or not the visitor ever notices.

03 · Accessibility

100/100 is a ceiling, not a floor.

The redesign scores a perfect 100/100 on Lighthouse accessibility (see the Deep Dive). That number is real — and it's also the easiest one in this whole series to over-trust.

Lighthouse's accessibility audit is a checklist: does every image have an alt attribute, does every control have a name, does contrast clear a ratio. It can tell you nothing is obviously broken. It cannot tell you whether that alt text is actually useful, whether the page makes sense read aloud in order, or whether a screen reader user comes away understanding what the page was trying to say.

  • 1Alt text existing isn't the same as alt text helping. The score checks whether the attribute is present. Listening checks whether hearing it out loud tells you anything you needed to know, or just that an image is there.
  • 2A valid reading order isn't the same as a reading order that makes sense. The audit confirms headings descend in sequence. It has no opinion on whether that sequence is how a person would actually want to explore the page.
  • 3An accessible name being present isn't the same as it being clear. A button can pass the check and still leave a screen reader user guessing at what happens when they activate it.

Getting past the score meant using the same screen-reader simulation built into the Deep Dive — the "Hear it" player next to the accessibility comparison — to actually listen to both sites end to end, not just confirm the audit had passed. That's where the redesign's copy earns the score instead of just clearing it: headline, trial terms, and section titles read back close to exactly as written, because they were written to be heard, not only seen.

The score didn't ask this question A perfect Lighthouse score has no opinion on whether a screen reader user actually enjoys using the site. That's a heuristic question, not an automated one — and the only honest way to answer it is to listen.
04 · Agentic Browsing

2 of 2 checks passed isn't the same as an agent succeeding.

The redesign passes PageSpeed's Agentic Browsing audit in full — 2 of 2 checks, both mobile and desktop (see the Research). That audit confirms a page can be parsed by an agent. It doesn't confirm an agent can actually get something done on it.

Those are two different tests. A checks-passed audit asks whether the content is structured in a way a machine could theoretically read. Actually pointing an agent at the page and asking it to do something — find the return window, compare two setups by price, add a specific configuration to a cart — asks whether it can.

The redesign's structured data — the schema.org Product markup carried on each Sactionals setup in the Deep Dive's working prototype — exists because of that second question, not the first. A page can pass every structural check and still leave an agent guessing, if the price or fit only lives inside a rendered tag instead of the page's own markup. Passing the audit was the floor. Making the actual task work was the target.

The Takeaway

Every score cited in this series — Lighthouse, PageSpeed, securityheaders.com — is a real, useful signal. None of them is the finish line.

A heuristic evaluation is what happens after the automated pass: reading the raw output instead of the badge, listening instead of assuming, and testing the actual task instead of the check that stands in for it.
